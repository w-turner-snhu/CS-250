## Transferable Skills
This course helped me improve my understanding of Agile development, Scrum, user stories, acceptance criteria, testing, and project organization. These skills will be useful in future programming courses and projects because they help explain how software requirements are understood, developed, and tested.

## Maintainability and Readability
I learned that clear requirements, organized documentation, and communication help make software easier to maintain and improve. User stories and acceptance criteria help the team understand how features should work, while testing helps identify problems. Project management tools such as Jira and Confluence can also help organize tasks and keep important information available to the team.

## Interpreting User Needs
I think understanding user needs starts with identifying what the user wants the program to do and why it is important. User stories help explain these needs from the user's perspective, while acceptance criteria provide details about how a feature should work. This information helps developers build the right features and helps testers determine whether the requirements have been met.

## Approaching Program Development
I approach program development by breaking the work into smaller tasks, understanding the requirements, and testing the results. In future development work, I hope to use Agile practices such as regular communication, reviewing progress, and getting feedback throughout development. These practices can help identify problems early and make it easier to adjust when requirements change.

## Being a Good Team Member
I think being a good team member means communicating clearly, completing assigned work, and helping address problems when they arise. Team members should ask questions when requirements are unclear and share information that could affect other people's work. Scrum also shows the importance of working together, listening to feedback, and taking responsibility for helping the team reach its goals.
